# MuMate Analytics — สรุปให้ทีม (16 ก.ย. 2026)

เอกสารนี้ตอบ 6 คำถาม: ทำอะไรไว้ · อะไรดูได้แล้ว · อะไรต้องรอ รอทำไม · หลังรอแล้วทำอะไรต่อ ·
จบแล้วได้อะไร จบวันไหน · พี่ปองต้องทำอะไรถ้าจะเข้าไปดู

---

## 1. โจทย์ที่ตั้งต้น

พี่ปองอยากรู้ **DAU ÷ Total users** ของ MuMate v2 และตัวเลขที่เกี่ยว: Active user, Recurring user,
Login, Sign up — "เบื้องต้นเอา DAU กับ Total users ก่อน"

ก่อนเริ่มทำ พบ 3 เรื่องที่ทำให้ตัวเลขเดิมใน GA ใช้ตอบโจทย์นี้ไม่ได้:

1. **GA นับ cookie ไม่ได้นับคน** — คนเดียวเปิดจาก LINE, Safari และแอปที่ติดตั้ง = 3 users
2. **"Total users" ของ GA คือคนเข้าชมในช่วงวันที่ ไม่ใช่จำนวนบัญชี** — ตัวหารที่ทีมต้องการคือบัญชีสมาชิก v2 ซึ่งอยู่ในฐานข้อมูล ไม่ได้อยู่ใน GA
3. **GTM ตัวเดียวโหลดทั้ง landing (mumate.co) และแอป (bazichart.mumate.co) รวมทั้ง Vercel preview** ลง property เดียวกัน → ตัวเลขปนกันหมด

ทางออกที่ตกลงกัน: **ตัวตั้ง (คน active) มาจาก GA แต่ต้องนับเฉพาะสมาชิกที่ล็อกอิน · ตัวหาร (สมาชิกทั้งหมด) มาจากฐานข้อมูล แสดงที่ /ops**

## 2. ทำอะไรไว้แล้วบ้าง

### GTM (container GTM-MLZC4FRC)

| เวอร์ชัน | เมื่อไหร่ | ทำอะไร |
|---|---|---|
| v3 "Guard hostnames" | 15 ก.ย. 20:05 | ใส่กติกาให้ tag ยิงเฉพาะบน `mumate.co`, `www.mumate.co`, `bazichart.mumate.co` — Vercel preview และ localhost ไม่ยิงอีกต่อไป ตัวเลขสะอาดตั้งแต่จุดนี้ |
| v4 "Members, login, sign_up" | 16 ก.ย. เช้า | Google tag ส่ง `user_id` (รหัสสมาชิกแบบเข้ารหัส) และ user property `member_state = member` เมื่อล็อกอิน · เพิ่ม tag สำหรับ event `login`, `sign_up`, `consent_update` · ทุก tag อยู่ใต้กติกา hostname เดียวกัน |

### GA4 (property G-EBZKXSF579 — property เดิม ไม่ได้สร้างใหม่)

- เก็บข้อมูลย้อนหลังได้ **14 เดือน** (เดิม 2 เดือน — ข้อมูลเดือนแรกจะเริ่มหายกลางตุลาถ้าไม่แก้)
- ถอดดาว key event `qualify_lead`, `close_convert_lead` ที่ Google ใส่มาเองและไม่มีข้อมูล
- **16 ก.ย.** ลงทะเบียน `member_state` เป็น custom dimension (scope ผู้ใช้) — ทำให้รายงานกรอง "เฉพาะสมาชิก" ได้

### แอป (mootech-fe PR #695 — production ตั้งแต่ 16 ก.ย. 05:17)

- ทางเดียวสำหรับทุก event (`lib/analytics/track.ts`) มี allowlist ชื่อ event และ parameter + เทสต์ที่แดงทันทีถ้ามีใครพยายามส่งข้อมูลต้องห้าม (วันเกิด, อีเมล, เบอร์, LINE id, ชื่อ, รหัสสมาชิกดิบ)
- `user_id` ที่ส่งให้ GA คือ **HMAC ของรหัสสมาชิกด้วยคีย์ที่อยู่บน Vercel เท่านั้น** — GA รู้ว่า "คนเดิม" แต่ระบุตัวตนกลับไม่ได้ ถ้าคีย์ไม่ถูกตั้ง ระบบจะไม่ส่ง id เลย ไม่มี fallback
- `login{method}` ยิงครั้งเดียวต่อการล็อกอินในเบราว์เซอร์ (method = line / google / facebook)
- `sign_up{method}` ยิงตอน first-run onboarding สำเร็จ = นิยามเดียวกับ "สมาชิก v2" ในฐานข้อมูล
- Consent mode ต่อกับหน้า consent ของแอป: ปิด "วิเคราะห์" = ไม่ส่งอะไรให้ Google
- หน้า checkout / QR / result **ไม่แตะ** — CSP ฝั่งจ่ายเงินเหมือนเดิม
- `lang="th"` ใน HTML

### /ops/analytics

- กล่อง **"สมาชิก v2 ทั้งหมด"** = จำนวนบัญชีที่ผ่าน first-run · วันนี้ +N · 7 วัน +N — ตรวจแล้วตรงกับ SQL เป๊ะ (15 · +0 · +4 ณ 16 ก.ย.)
- ซ่อม `OPS_ADMIN_SECRET` ฝั่ง engine ที่ค่าไม่ตรงกับ FE → ส่วน "เศรษฐกิจ QI" กลับมาแสดงผล

## 4. อะไรต้องรอ · รอทำไม

**รอ Google 24–48 ชั่วโมง (ถึง 17–18 ก.ย.)** — custom dimension `Member state` ที่เพิ่งลงทะเบียน
Google ต้องประมวลผลก่อนจึงจะโผล่ให้เลือกในรายงานและ Exploration ได้ นี่คือกติกาของ Google
(support.google.com/analytics/answer/14239618) ไม่ใช่สิ่งที่เราเร่งได้

**รอเก็บข้อมูล 7 วัน** — DAU วันเดียวบอกอะไรไม่ได้ และเราต้องพิสูจน์ 2 อย่างที่ยังไม่เคยเห็น:
- `sign_up` ใน GA ต้องเท่ากับสมาชิกใหม่ในฐานข้อมูล (ยังไม่มีสมาชิกใหม่ตั้งแต่ v4 live เลยยังไม่เห็นตัวจริง)
- คนเดียวกันสองเครื่องต้องนับเป็น 1 (เห็นกลไกใน DebugView แล้ว แต่ยังไม่เห็นผลรวม)

**ทำไม GA ถึงมีโอกาสนับต่ำกว่าจริง** — คนที่ใช้ ad blocker หรือปิด consent "วิเคราะห์" จะไม่ถูกนับใน GA
แต่ยังเป็นสมาชิกในฐานข้อมูล 7 วันนี้จะบอกว่าช่องว่างนี้ใหญ่แค่ไหน

## 6. จบแล้วได้อะไร · จบวันไหน

- **Report** — ตาราง 7 วัน (active 1 วัน, active 7 วัน, login, sign_up, สมาชิกทั้งหมด, **% DAU**) · ผลพิสูจน์ว่า GA ตรงกับฐานข้อมูลไหม · GA นับต่ำกว่าจริงกี่ % · ตัวเลขนี้บอกอะไรได้และไม่ได้

## 7. พี่ปองต้องทำอะไรถ้าจะเข้าไปดู

**สิทธิ์ที่ต้องมี**
- GA4: สิทธิ์ดู property G-EBZKXSF579 (บัญชี GA ของทีมเอง — ถ้าเข้า GA แล้วเห็น property "MuMate" ก็คือมีแล้ว)
- /ops: ต้องมีบัญชี ops (ฟีมเป็นคนเพิ่มให้) — เปิด `bazichart.mumate.co/ops/analytics`

**ดูได้ตอนนี้**
1. `/ops/analytics` → กล่อง "สมาชิก v2 ทั้งหมด" = Total users
2. GA4 → เรียลไทม์ → เลื่อนหาการ์ด "ผู้ใช้ที่ใช้งานอยู่ โดย พร็อพเพอร์ตี้ผู้ใช้" → dropdown เลือก `member_state` → เห็นสมาชิกที่ออนไลน์ใน 30 นาที

**ดูได้ตั้งแต่ ~18 ก.ย.** (หลังฟีมสร้าง Exploration)
3. GA4 → สำรวจ → "Members daily" → แท็บแรก = DAU/recurring รายวัน · แท็บ Events = login/sign_up รายวัน
4. รายงานปกติของ GA ก็กรองได้: ปุ่ม "เพิ่มการเปรียบเทียบ" ด้านบนรายงาน → มิติ `Member state` ตรงกันทั้งหมด `member`

**ข้อควรระวังตอนอ่าน GA**
- ตัวเลขที่เชื่อได้เริ่ม **16 ก.ย.** — ก่อนหน้านั้นเป็น cookie ปนคนเข้า landing และ preview
- "วันนี้" ของ GA ยังไม่นิ่ง ประมวลผลเสร็จใน 24–48 ชม. → ดู "เมื่อวาน" เป็นหลัก
- "Total users" ของ GA ≠ จำนวนสมาชิก — ตัวหารที่ถูกอยู่ที่ /ops เท่านั้น
- ถ้าจะใส่ marketing pixel เพิ่มใน GTM ทำได้เลย แค่บอกในแชทก่อน publish (ตามที่คุยกันไว้)

### Parameter ที่ดูได้แล้วใน GA (ตั้งแต่ v4)

| ประเภท | ชื่อ | ค่า | ความหมาย |
|---|---|---|---|
| Event | `login` | — | สมาชิกล็อกอินในเบราว์เซอร์นี้ (ครั้งเดียวต่อล็อกอิน ไม่ใช่ต่อหน้า) |
| Event | `sign_up` | — | สมาชิกใหม่ผ่าน first-run สำเร็จ |
| Event | `consent_update` | — | สมาชิกเปลี่ยนสวิตช์ consent |
| Event parameter | `method` | `line` / `google` / `facebook` | ล็อกอินด้วยอะไร (อยู่ใน login และ sign_up) |
| User property | `member_state` | `member` | คนนี้เป็นสมาชิกที่ล็อกอินแล้ว — ใช้กรองทุกรายงาน |
| User-ID | `user_id` | รหัส 32 ตัวอักษร | "คนเดิม" ข้ามอุปกรณ์ — อ่านกลับเป็นตัวตนไม่ได้ |
| Event (Google ให้เอง) | `page_view`, `session_start`, `first_visit`, `user_engagement`, `scroll`, `form_submit` | — | จาก enhanced measurement เหมือนเดิม |

**สิ่งที่ไม่มีใน GA และจะไม่มี:** วันเกิด, เวลาเกิด, ธาตุ, ราศี, ชื่อ, อีเมล, เบอร์, LINE id, รหัสสมาชิกดิบ —
allowlist ในโค้ดกันไว้ และการเพิ่มต้องผ่านการตัดสินใจใหม่

## 8. สิ่งที่อาจทำต่อ (ยังไม่เริ่ม)

**"3-lite" — % DAU สดใน /ops** — ให้แอปบันทึกว่าสมาชิกคนไหนเข้าใช้วันไหนลงฐานข้อมูล แล้ว /ops
คำนวณ DAU และ % เอง ไม่พึ่ง GA ตัวตั้งกับตัวหารมาจากที่เดียวกัน ไม่มี lag ไม่มี ad blocker
งานเล็ก (1 migration + 1 บรรทัดตอนโหลดหน้า + 1 SQL + 1 บรรทัดในกล่อง) แต่**ยังไม่ทำตอนนี้**
รอตัวเลข 7 วันก่อน — ถ้า GA ต่ำกว่าฐานข้อมูลมาก 3-lite จำเป็น ถ้าแทบไม่ต่าง อาจไม่ต้องทำเลย
