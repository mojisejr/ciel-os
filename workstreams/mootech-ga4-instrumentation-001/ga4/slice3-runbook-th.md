# Slice 3 — Runbook ฟีม ↔ ผม (เมนู GA4 ภาษาไทย)

ฟีมบอกผม **4 ครั้ง** ตลอด slice นี้: ① เวลาลงทะเบียน · ② แถวแรกโผล่ · ③ CSV วันที่ 7 · ④ พี่ปองว่าไง
ที่เหลือคือรอ Google กับรอวัน

ชื่อเมนูภาษาไทยด้านล่างมาจากความจำของผม ยังไม่ได้เปิด GA ภาษาไทยเทียบ — ถ้าคำไม่ตรง
ให้ยึดคำอังกฤษในวงเล็บ (GA แสดงชื่อ dimension/metric บางตัวเป็นอังกฤษแม้ตั้งภาษาไทย)

## วันที่ 0 — วันนี้ (16 ก.ย.) · ฟีม ~5 นาที

### ขั้น 1 ลงทะเบียน `member_state`

1. GA4 → ซ้ายล่าง ไอคอนฟันเฟือง **ผู้ดูแลระบบ** (Admin)
2. คอลัมน์ *พร็อพเพอร์ตี้* → หัวข้อ **การแสดงข้อมูล** (Data display) → **คำจำกัดความที่กำหนดเอง** (Custom definitions)
3. แท็บ **มิติข้อมูลที่กำหนดเอง** (Custom dimensions)
4. **ดูก่อน** — มีแถวที่ *พร็อพเพอร์ตี้ผู้ใช้* = `member_state` อยู่แล้วไหม
   - มีแล้ว → ข้ามไป ① เลย บอกผมว่า "มีอยู่แล้ว"
   - ไม่มี → ทำข้อ 5
5. ปุ่ม **สร้างมิติข้อมูลที่กำหนดเอง** (Create custom dimension)
   - ชื่อมิติข้อมูล (Dimension name): `Member state`
   - ขอบเขต (Scope): **ผู้ใช้** (User) ← ไม่ใช่ "เหตุการณ์"
   - คำอธิบาย (Description): `member = signed-in v2 member`
   - พร็อพเพอร์ตี้ผู้ใช้ (User property): `member_state` ← ตัวเล็กทั้งหมด มี `_`
6. **บันทึก** (Save)

> **① บอกผม:** "ลงทะเบียนแล้ว HH:MM" หรือ "มีอยู่แล้ว"
> **ผมทำ:** จดเวลาไว้เป็นหลักฐานใน closeout ยังไม่มีอะไร commit

### (ถ้าอยากเช็คว่า tag ยังส่งอยู่ — 1 นาที ไม่บังคับ)

**รายงาน** (Reports) → **เรียลไทม์** (Realtime) → เลื่อนหาการ์ด **ผู้ใช้ที่ใช้งานอยู่ โดย พร็อพเพอร์ตี้ผู้ใช้**
(Users by User property) → dropdown เลือก `member_state` → ควรเห็น `member` อย่างน้อย 1
(ตัวฟีมเอง ถ้าเปิดแอปค้างไว้) — ไม่ต้องบอกผมถ้าเห็น บอกเฉพาะถ้า**ไม่**เห็น

## วันที่ 1–2 (17–18 ก.ย.) · ฟีม ~10 นาที ครั้งเดียว

Google ใช้เวลา 24–48 ชม. ลองทำขั้น 2 วันที่ 17 ถ้าหา `Member state` ไม่เจอ ให้มาทำวันที่ 18

### ขั้น 2 สร้าง Exploration

1. เมนูซ้าย **สำรวจ** (Explore) → การ์ด **ว่างเปล่า** (Blank)
2. ชื่อซ้ายบน (ตรงคำว่า *การสำรวจที่ไม่มีชื่อ*): `Members daily`
3. คอลัมน์ **ตัวแปร** (Variables) ซ้ายสุด:
   - **ช่วงวันที่** (Date range) → กำหนดเอง → เริ่ม = วันที่ลงทะเบียน (ข้อ ①) ถึงวันนี้
   - **มิติข้อมูล** (Dimensions) กด **+** → ช่องค้นหา พิมพ์แล้วติ๊ก 3 ตัว:
     `วันที่` (Date) · `Member state` (อยู่แท็บ *กำหนดเอง* Custom) · `ชื่อเหตุการณ์` (Event name)
     → **นำเข้า** (Import)
   - **เมตริก** (Metrics) กด **+** → ติ๊ก 3 ตัว:
     `ผู้ใช้ที่ใช้งานอยู่ 1 วัน` (1-day active users) · `ผู้ใช้ที่ใช้งานอยู่ 7 วัน` (7-day active users) · `จำนวนเหตุการณ์` (Event count)
     → **นำเข้า**
4. คอลัมน์ **การตั้งค่าแท็บ** (Tab settings) ถัดมา:
   - **แถว** (Rows): ลาก `วันที่` มาวาง
   - **แสดงแถว** (Show rows): 25
   - **ค่า** (Values): ลาก `ผู้ใช้ที่ใช้งานอยู่ 1 วัน` และ `ผู้ใช้ที่ใช้งานอยู่ 7 วัน`
   - **ตัวกรอง** (Filters) ล่างสุด: คลิก → เลือก `Member state` → เงื่อนไข **ตรงกันทั้งหมด** (exactly matches) → พิมพ์ `member` → **ใช้** (Apply)
5. ตารางขวา: 1 แถว = 1 วัน มี 2 ตัวเลข

### แท็บที่ 2 — login / sign_up

6. ด้านบนตาราง กด **+** ข้างชื่อแท็บ → เพิ่มแท็บ *รูปแบบอิสระ* (Free form) → ตั้งชื่อ `Events`
7. **แถว**: `วันที่` · **คอลัมน์** (Columns): `ชื่อเหตุการณ์` · **ค่า**: `จำนวนเหตุการณ์`
8. **ตัวกรอง** 2 อัน:
   - `Member state` ตรงกันทั้งหมด `member`
   - `ชื่อเหตุการณ์` **ตรงกับนิพจน์ทั่วไป** (matches regex) `^(login|sign_up)$`
9. ตาราง: 1 แถว = 1 วัน คอลัมน์ `login` และ `sign_up`

Exploration บันทึกเองอัตโนมัติ

> **② บอกผม:** "Exploration เสร็จ เห็นแถวแรกวันที่ __" + screenshot แท็บแรก 1 รูป
> ถ้าตารางว่าง/หา Member state ไม่เจอหลังพ้น 48 ชม. → ส่ง screenshot หน้า *คำจำกัดความที่กำหนดเอง* มาแทน
> **ผมทำ:** อ่าน screenshot ยืนยันว่า filter ถูก → กำหนด **วัน D1** = วันแรกที่มีแถว → บอกฟีมว่า
> "วันที่ 7 คือวันที่ __ รอได้เลย" — ระหว่างนี้ผมไม่ทำอะไร

## วันที่ 7 (D1 + 6) · ฟีม ~3 นาที

### ขั้น 4 Export

1. เปิด **สำรวจ** → `Members daily`
2. **ช่วงวันที่** เลื่อนวันสิ้นสุดเป็นวันนี้ (ครอบ D1 ถึง D7)
3. ขวาบน ไอคอน **ส่งออก** (Export, ลูกศรลง) → **ดาวน์โหลด CSV** (Download CSV)
4. สลับไปแท็บ `Events` → ส่งออก CSV อีกไฟล์

> **③ ส่งผม:** CSV 2 ไฟล์ (ในไฟล์มีแค่วันที่ ตัวเลข ชื่อ event — ไม่มีข้อมูลใคร)
> **ผมทำ (วันเดียวเสร็จ):**
> 1. รัน SQL อ่านอย่างเดียวบน pooler (query เดิมจาก slice 2) → `members_total` ณ สิ้นวันของแต่ละวัน D1–D7 จาก `onboarded_at`
> 2. ตาราง 7 แถว: active 1-day · active 7-day · login · sign_up · members_total · **% = active 1-day ÷ members_total**
> 3. เทียบ Σ`sign_up` (GA) กับ members_total(D7) − members_total(D0) (DB) → ต้องเท่ากัน ±1 วันขอบ ถ้าไม่ = อธิบาย
> 4. วัดช่องว่าง: login/active ใน GA เทียบกับ DB → ตัวเลข "GA นับต่ำกว่าจริง X%"
> 5. เขียน **1 หน้าสำหรับพี่ปอง** (ไทย) ที่ `ga4/report-for-team.md`:
>    ครึ่งบน **Report** — ตาราง, %, ผลเทียบ, ข้อจำกัด
>    ครึ่งล่าง **Runbook** — 5 อย่างที่ขอ ดูที่ไหน, เปิด Exploration ยังไง, อ่าน /ops ตรงไหน, อันไหนสด/อันไหนช้า, เช็คเองยังไงว่า 2 จอตรงกัน
> 6. commit บน standing branch ที่ HQ กำหนด → ส่งลิงก์/ไฟล์ให้ฟีม

## วันที่ 7–8 · ฟีม

เอาหน้านั้นไปให้พี่ปองอ่าน (ส่งไฟล์ หรือเปิดให้ดู) ถามเขา 2 คำถาม:
- ตัวเลขนี้ตอบที่อยากรู้ไหม
- อยากเห็นอะไรเพิ่ม

> **④ บอกผม:** คำตอบพี่ปอง (ถ้าเขาขอเพิ่ม บอกมาเป็นคำพูดเขาเลย)
> **ผมทำ:**
> 1. เขียน closeout event: 7 แถว, ผลเทียบ, วัน D1, คำตอบพี่ปอง, สิ่งที่ขอเพิ่มเป็น *candidate* (ยังไม่เริ่ม)
> 2. bun run check + Wake → commit → รายงาน HQ
> 3. **slice 3 จบ · workstream นี้จบ**
> 4. ถามฟีมคำเดียว: จะเปิด workstream ใหม่สำหรับ **3-lite** (% สดใน /ops) เลยไหม หรือพอแค่นี้ก่อน
