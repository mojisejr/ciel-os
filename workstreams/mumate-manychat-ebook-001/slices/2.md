# Slice 2 — ตรวจสลิปและส่งของบน staging

ทำแทนแอดมินตามที่ทีมทำมือทุกวันนี้: ตรวจสลิป แล้วส่งข้อความเดียวกับที่แอดมินส่ง (revision 0.4)

## Scope

**รับสลิป (flow `[TEST] E-Book 95`)**
- ต่อจาก keyword `mmbot test` ด้วยขั้นสั่งซื้อและรอรูปสลิป เก็บรูปใน field `bot_slip`
- ได้รูปแล้ว → External Request ส่ง subscriber id และลิงก์รูปไปที่แอป แอปตอบทันที แล้วค่อยตรวจ

**ตรวจสลิป**
- เรียก Slip2Go `https://connect.slip2go.com/api/verify-slip/qr-image-link/info` ด้วย 3 เงื่อนไข:
  - `checkDuplicate`
  - `checkReceiver`: ธนาคาร (`01004`) กับเลขบัญชีเท่านั้น ไม่ตรวจชื่อ
    เพราะสลิปจริงเขียนชื่อย่อ "บจก. มูเทค เดสตินี่" ไม่ตรงกับชื่อเต็ม
  - `checkAmount` แบบ `eq` กับราคาของ env นั้น (staging 1 บาท)
- ตารางของเราเก็บ `transRef` ไม่ให้ซ้ำ เป็นด่านที่สองถัดจาก Slip2Go
- ผ่านเมื่อได้ `200200` เท่านั้น code อื่นแยกตามกลุ่มใน PLAN.md revision 0.3:
  ไม่ผ่าน → บอกลูกค้าและแจ้งแอดมิน · ลองใหม่ได้ → เข้าคิว · `401xxx` → alert ถึงทีม · ไม่รู้จัก → แอดมิน

**ผ่าน: ส่งของแบบเดียวกับที่แอดมินส่ง**
- บันทึกออเดอร์ว่าจ่ายแล้ว
- ติด tag `bot_paid` แล้ว `sendFlow` ไปยัง flow ส่งของใน ManyChat ภายใน 24 ชั่วโมงของลูกค้า
- flow ส่งของมีข้อความเดียวกับที่ทีมส่งเอง ทีมแก้ข้อความใน ManyChat ได้เองโดยไม่ต้องแก้แอป:
  - ลิงก์ E-Book (Drive folder เดิม)
  - คูปอง Mumate Plus 1 เดือน `EBOOKPULS95` และลิงก์ `bazichart.mumate.co/v2/account`
  - รูป "วิธีการกรอกโค้ด"
- request ซ้ำจาก ManyChat หรือสลิปเดิมส่งซ้ำ → ส่งของครั้งเดียว

**ไม่ผ่าน**
- บอกเหตุผลลูกค้าเป็นภาษาคน
- ติด tag เหตุผลที่ขึ้นต้นด้วย `bot_` และแจ้งแอดมินเหมือนทุกวันนี้

**เครื่องมือดูแลใน mumate-infra**
- `env/ebook.env.example` เพิ่ม `SLIP2GO_SECRET_KEY`, ราคา และบัญชีผู้รับ
  ใส่ค่าจริงบน mumate-2 ด้วย `bin/env-set.sh` จาก `.assets/mumate/manychat/.env`
- `bin/ebook.sh orders|pending|resend|mark-paid --reason`
- ทุกคำสั่งมี `--dry-run` และคำสั่งที่เขียนข้อมูลบันทึกเสมอว่าใครสั่งและสั่งเพราะอะไร

**ไม่ทำใน slice นี้ (ย้ายไปหลังปล่อยจริง ดู PLAN.md revision 0.4)**
- ลิงก์ส่วนตัวต่อออเดอร์ การประทับเลขออเดอร์บน PDF และการย้าย PDF ไป private storage
- การคัดลอกรูปสลิปเก็บใน bucket และงานลบรูป 30 วัน
- ข้อความ PDPA (ร่างไว้ที่ `.assets/mumate/manychat/pdpa-draft.md`)

## Acceptance

- บน staging เจ้าของโอนจริง 1 บาทแล้วส่งสลิป → ได้ลิงก์ E-Book, คูปอง และรูปวิธีกรอกในแชท
  → ออเดอร์เป็น paid → `bin/ebook.sh orders` เห็นออเดอร์นั้น
- กรณีที่ต้องถูกปฏิเสธพร้อมเหตุผล ไม่ส่งของ และแจ้งแอดมิน:
  - สลิปเดิมส่งซ้ำ
  - ยอดผิด
  - รูปที่ไม่ใช่สลิป
  - บัญชีผู้รับผิด
- request เดียวกันจาก ManyChat มาซ้ำ → ส่งของครั้งเดียว
- `bin/ebook.sh mark-paid --reason` ส่งของให้ออเดอร์ที่ค้างได้ และบันทึกว่าใครสั่ง
- flow จริง "Bazi E-Book 95" ไม่เปลี่ยน ตรวจโดยเทียบกับ export วันที่ 2026-11-08 แล้วต่างกันแค่ตัวเลขสถิติ
- test ครอบทุกกรณีข้างบนด้วยคำตอบของ Slip2Go ที่บันทึกไว้ ไม่ยิงบริการจริงตอน test
  รวมทุก code ใน revision 0.3 และกรณี `200000` ต้องไม่นับว่าผ่าน
- `scripts/test-all.sh` ของ mumate-infra ผ่าน, test ของแอปผ่าน และไม่มี secret ใน repo ใด
