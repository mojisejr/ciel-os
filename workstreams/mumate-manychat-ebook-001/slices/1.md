# Slice 1 — โครงแอปและทางทดสอบบน staging

## Scope

- สร้าง repo ส่วนตัวของแอปตามที่เจ้าของอนุมัติชื่อ ลงทะเบียนเป็น project ใน ciel-os
  มี `container-build` ที่สร้าง image tag = git SHA
- แอปมี `/api/health` และ endpoint หนึ่งตัวที่รับ External Request จาก ManyChat
  ตอบภายใน 1 วินาทีเสมอ แล้วค่อยทำงานต่อ
- แอปตรวจลายเซ็นหรือ secret ของ request ที่มาจาก ManyChat
- แอปมีด่านกันพลาด: บน staging เรียก ManyChat API ได้เฉพาะ subscriber ใน allowlist ของทีม
- mumate-infra เพิ่ม service ตัวที่สาม, Caddy route ของ staging, `env/*.example`
  และให้ `release`, `staging-follow`, `promote-production`, `rollback` รู้จักแอปนี้
  ยังไม่เปิดบน production
- ตารางแรกบน `pgstaging`: รับ event ของแต่ละ request (subscriber, ขั้น, เวลา)
  migration เป็นแบบเพิ่มอย่างเดียว รันซ้ำได้
- ManyChat: flow สำเนา "E-Book 95 [TEST]" ที่เข้าได้เฉพาะคนที่มี tag `tester`
  ให้ External Request ชี้ไป staging และตอบกลับด้วยข้อความทดสอบผ่าน `sendContent`

## Acceptance

- merge แล้ว staging deploy แอปเองภายใน 3 นาที, `bin/ops-status.sh` ✅ และ Discord ประกาศ
- คนในทีมที่มี tag `tester` ทักคำทดสอบ → ได้ข้อความตอบกลับจาก staging ในแชท
  → มีแถว event ใน `pgstaging`
- subscriber ที่ไม่อยู่ใน allowlist → แอปไม่ส่งข้อความหา และบันทึกว่าถูกกัน
- flow จริง "Bazi E-Book 95" ไม่เปลี่ยน ลูกค้าจริงไม่เห็นอะไรต่างจากเดิม
- `scripts/test-all.sh` ของ mumate-infra ผ่าน, test ของแอปผ่าน และไม่มี secret ใน repo ใด
