# Slice 3 — ปล่อยจริงบน production

ลำดับเดิมเป็น slice 4 ย้ายมาก่อนข้อมูลคนจ่ายและไม่จ่ายใน revision 0.5

## Scope

**ทางถอยของแอปก่อนอย่างอื่น**
- `release`, `promote-production`, `rollback-production` และ `bin/rollback.sh` รู้จัก ebook
  ถอย ebook ได้โดยไม่แตะ fe และ bazi
- deploy ebook ไม่มีช่วงที่ `/ebook-api` ตอบไม่ได้ (วันนี้ดับราว 6 วินาทีตอนสร้าง container ใหม่)
  หรือ ManyChat ลองเรียกซ้ำเมื่อเรียกไม่ติด เลือกวิธีตอนทำ

**ก่อน promote**
- รัน migration ของงานนี้บน Supabase production เมื่อเจ้าของสั่ง ผ่าน `bin/prod-sql.sh`
- ใส่ env ของ production ทีละค่าตาม runbook 01:
  - ManyChat API key
  - Slip2Go URL และ secret
  - ราคาจริง
  - บัญชีผู้รับ
- ตั้ง IP whitelist ของ Slip2Go เป็น IP ของ mumate-2 และ mumate-prod-1 แล้วลบ `*`
- เปลี่ยน hook secret ของ staging และ Slip2Go secret key ใหม่ (ค่าเดิมเคยโผล่ใน screenshot ของ agent)

**promote**
- เจ้าของกด `promote-production` ด้วย SHA เดียวกับที่ผ่าน staging

**ก่อนแก้ flow จริง**
- Duplicate "Bazi E-Book 95" เก็บไว้เป็น backup แล้วจด version ที่ publish อยู่
- จุดเทียบคือ flow ตามที่ `mumate-manychat-copy-001` publish เมื่อ 2026-11-09 ไม่ใช่ export วันที่ 2026-11-08
- ข้อความเตือนของ ManyChat ตอนลูกค้าส่งสิ่งที่ไม่ใช่รูป เป็นภาษาไทยแบบที่ flow จริงใช้

**จุดที่แก้ใน flow จริง**
- แก้จุดเดียว คือเพิ่ม External Request หลังได้สลิป เฉพาะลูกค้าที่มี tag `bot_beta`
- ขั้นเดิมที่ติด `eb_slip_sent`, เปิดแชท และแจ้งแอดมิน ยังทำงานทุกครั้ง
  ข้อความแจ้งแอดมินบอกว่าแอปส่งของให้แล้ว หรือยังต้องให้แอดมินทำเอง
- แอดมินยังส่งของเองได้ทุกกรณี บอทไม่ได้มาแทนขั้นเดิม

**ปล่อย 2 ขั้น**
- ขั้นแรก: เปิดเฉพาะ `bot_beta` คือเจ้าของและคนในทีม 1–2 คน ซื้อจริงด้วยราคาจริง
- ขั้นสอง: เจ้าของสั่งเปิดให้ทุกคน หลังจ่ายแพ็กของ Slip2Go และ ManyChat Pro

**ทางถอย**
- ถอด External Request ออกจาก flow จริง หรือใช้ `rollback-production`
- ทั้งสองทาง flow กลับไปเป็นแบบเดิม 100% เพราะไม่เคยลบขั้นเดิมออก

**alert**
- control room เห็นแอปตัวที่สาม (health, log silence)

## Acceptance

ผ่านทีละด่าน ด่านไหนไม่ผ่านให้หยุด ลูกค้าจริงยังใช้ flow เดิมตลอด

1. ซ้อมบน staging ด้วย flow ทดสอบที่ตั้งเหมือนของจริงและเสียบแอปจุดเดียวแบบเดียวกัน
   - ส่งสลิป → แอปส่งของ และแอดมินยังได้แจ้ง
   - ปิดแอปแล้วส่งสลิป → ลูกค้ายังได้ข้อความเดิม และแอดมินยังได้แจ้ง ใช้เป็นหลักฐานว่า flow ไม่พังแม้แอปล่ม
2. แอปขึ้น production โดยยังไม่มี flow ไหนเรียก health และฐานข้อมูลผ่าน alert เห็นแอป
3. ซ้อม rollback ของ ebook บน production หนึ่งรอบก่อนมีลูกค้าใช้ fe และ bazi ไม่ถูกแตะ
4. ลูกค้าคนแรกในขั้น `bot_beta` ได้ของอัตโนมัติ และแอดมินยืนยันว่าเงินเข้าบัญชีจริง
5. เปิดให้ทุกคนเมื่อเจ้าของสั่ง

ทุกด่าน:
- ไม่มีลูกค้าคนไหนถูกทิ้ง: สลิปที่ระบบตรวจไม่ได้ไปถึงแอดมินทุกใบ
- runbook 00 และ 01 มีขั้นของแอปนี้ และเจ้าของกดถอยจากมือถือได้
