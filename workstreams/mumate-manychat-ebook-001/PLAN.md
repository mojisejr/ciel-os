## เป้าหมาย

วันนี้ flow "Bazi E-Book 95" ใน ManyChat ทำงานเองจนลูกค้าส่งสลิป หลังจากนั้นแอดมินทำเองทั้งหมด:
ดูยอดเงินเข้าในบัญชีกสิกร แล้วส่งลิงก์ PDF กับโค้ดแอปในแชท ManyChat จึงไม่รู้ว่าใครจ่ายเงินจริง
(บันทึกการอ่าน flow อยู่ที่ `memory/events/2026/11/08/20261108T225510_mumate_manychat_ebook95_flow_reviewed.yaml`)

งานนี้คือหลังบ้านที่ทำส่วนของแอดมินแทน ให้ agent ช่วยเจ้าของดูแลจากแชทได้ และเก็บข้อมูลว่าใครจ่าย ใครไม่จ่าย

## ข้อตกลงกับเจ้าของ

### revision 0.1 (2026-11-08)

- **ทาง A:** ลูกค้ายังโอนเข้าบัญชีบริษัทแล้วส่งสลิปเหมือนเดิม ระบบตรวจสลิปเอง ไม่ใช้ payment gateway
  เพราะทีมไม่อยากรวมกับระบบจ่ายเงินของแอป (Beam) และไม่อยากเสียค่าธรรมเนียม
- **ปล่อยแบบ fe และ bazi:** merge แล้ว staging deploy เอง ทีมทดลองบน staging ก่อน จากนั้นเจ้าของกด promote
- **ฐานข้อมูลเดียวกับ MuMate:** production ใช้ Supabase ตัวเดียวกับแอป ตารางของงานนี้แยกเป็นของตัวเองและเพิ่มอย่างเดียว
  staging ใช้ `pgstaging` บน mumate-2

### revision 0.2 (2026-11-08)

- **repo:** แอปอยู่ใน repo ส่วนตัวแยกของตัวเอง mumate-infra เก็บแค่การรัน (service, Caddy, env, release)
  และเครื่องมือดูแลใน `bin/` ที่ agent ใช้จากแชท เช่น ดูออเดอร์วันนี้ สลิปที่ค้าง ส่งลิงก์ใหม่ ยืนยันจ่ายด้วยมือพร้อมเหตุผล
  ทุกคำสั่งมี `--dry-run` และทุกการเขียนบน production บันทึกเป็น closeout หนึ่งรายการ
- **บริการตรวจสลิป: Slip2Go** (ทีมเลือก) ใช้ endpoint ที่รับลิงก์รูป `qr-image-link` ตรวจสลิปซ้ำ บัญชีผู้รับ และยอดเงิน
  API URL ของแต่ละบัญชีไม่เหมือนกัน ต้องเอามาจาก dashboard ของบัญชีนั้น และ IP whitelist ต้องมี IP ของทั้งสองเครื่อง
- **ห้ามให้ flow ที่ใช้อยู่จริงพัง (สำคัญที่สุด):**
  - ไม่แก้ flow "Bazi E-Book 95" ไม่เปลี่ยนชื่อ ไม่ลบ tag, field และ trigger เดิม (`eb_slip_sent`, `ebook_slip` ฯลฯ)
    จนถึง slice 4
  - งาน slice 1–3 ทำใน flow สำเนา `[TEST]` ที่เปิดด้วย keyword ทดสอบ ซึ่งต้องไม่มีคำใดคำหนึ่งใน keyword ของ flow จริง
    และใช้ tag กับ field ใหม่ที่ขึ้นต้นด้วย `bot_` เท่านั้น
  - ตอนปล่อยจริง flow จริงเปลี่ยนแค่จุดเดียว คือเพิ่มการเรียกแอปหลังได้สลิป โดยทางเดิมที่ติด tag และแจ้งแอดมินยังทำงานทุกครั้ง
    ถ้าแอปตอบช้า ล่ม หรือตอบผิด ลูกค้ายังได้ข้อความเดิม และแอดมินยังได้แจ้ง
    ก่อนแก้ต้อง Duplicate flow จริงเก็บไว้เป็น backup
- **ต่อยอดจากของที่ทีมมี:** ไม่ยุ่งกับงานที่ทีมทำไว้ก่อน รายการข้อ 1–4 ที่เคยคุยกับ Codex ไม่ใช้แล้ว
- **รูปสลิปเก็บ 1 เดือน** ใน Supabase storage ตัวเดียวกับ fe โดยแยกเป็น private bucket ของงานนี้
  แบ่งโฟลเดอร์ตาม env และเดือน และมีงานตั้งเวลาลบรูปที่เก็บครบ 30 วัน
  ผลการตรวจ (transRef ยอด เวลา ชื่อผู้โอนแบบที่ Slip2Go ส่งมา) อยู่ในตาราง ใช้ทำหลังบ้านและ dashboard
- **PDF และลิงก์ (agent เสนอ เจ้าของยืนยันตอน decision ของ slice 2):**
  - PDF ต้นฉบับอยู่ใน private storage ไม่ใช้ลิงก์ Google Drive ที่เปิดได้ทุกคน
  - ลูกค้าได้ลิงก์ส่วนตัวต่อออเดอร์ แอปเช็ค token ก่อน แล้วค่อยส่งต่อไปที่ลิงก์ของ storage ที่หมดอายุในไม่กี่นาที
  - ลิงก์ส่วนตัวมีอายุจำกัดและจำกัดจำนวนครั้งที่ดาวน์โหลด ขอลิงก์ใหม่ได้ในแชทเดิม
  - ทุกหน้าของ PDF ประทับชื่อหรือเลขออเดอร์ของผู้ซื้อ ไฟล์ที่ดาวน์โหลดไปแล้วกันการส่งต่อไม่ได้ 100%
    แต่ไฟล์ที่หลุดไปจะสืบได้ว่ามาจากออเดอร์ไหน

## สิ่งที่ต้องได้ก่อน decision ของ slice 1

- ManyChat ใช้แผน Pro ขึ้นไปหรือไม่ และมี API key อยู่แล้วหรือเปล่า
  ถ้ามีแล้วให้ใช้ key เดิม ห้ามกด generate ใหม่ เพราะของเดิมที่ใช้ key อยู่อาจพัง
- ชื่อ repo และชื่อ host ของแอป
- รายชื่อคนในทีมที่เป็น tester (Facebook account ที่ทักเพจได้)
- บัญชี Slip2Go: API URL, secret key และการใส่ IP ใน whitelist

ส่วนที่ต้องได้ก่อน slice 2: ไฟล์ PDF, วิธีออกโค้ดแอปฟรี 1 เดือน, ชื่อบัญชีผู้รับที่ตรงกับธนาคาร และข้อความที่จะใช้ตอบลูกค้า
