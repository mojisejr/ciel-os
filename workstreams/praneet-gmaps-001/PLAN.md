## เป้าหมายและข้อตกลงกับเจ้าของ

เจ้าของปักหมุดร้านบน Google Maps ไว้นานแล้ว และโปรไฟล์ยืนยันมานานแล้ว ช่วงหลังมีคนโทรเข้ามาจาก Maps บ่อย
แต่หลายสายค้นหา "ป้าปราณี" ไม่ใช่ "ปราณีต" เจ้าของอยากให้ agent ดูแลเรื่องนี้ผ่าน office แบบเดียวกับ MuMate
และถามต่อว่า "เราจะ เปลี่ยน ลูกค้าที่เข้ามาดูผ่าน แมพเป็นคนซื้อได้ยังไงด้วย"

เจ้าของยืนยันข้อตกลงนี้เมื่อ 2026-10-25 หลัง syncup 3 รอบ ("ยืนยันครับ เปิด workstream ได้เลย")

- **ผลที่ต้องการ:** office ช่วยเปลี่ยนคนที่เจอร้านบน Maps เป็นคนซื้อ และวัดได้ทุกขั้น:
  เห็นร้าน → โทร / กดเข้าเว็บ → กดทัก LINE → ออเดอร์ ถ้า office ทำส่วนนี้ได้ถือว่าจบ
  ("ถ้า office ทำงานส่วนนี้ได้ก็ถือว่าจบครับ") และ office ช่วย broadcast LINE ได้ด้วย
- **อ่านตัวเลขอย่างเดียวก่อน:** ไม่แก้โปรไฟล์ ไม่โพสต์ ไม่ตอบรีวิวผ่าน API ("ดูตัวเลขอย่างเดียวดูก่อนครับ แล้วเดี๋ยวเราค่อยเพิ่ม")
- **เป็น tool ใน office ไม่ใช่ script ที่เขียนสด และไม่รันเอง:** เจ้าของเรียกผ่าน session เมื่อต้องใช้
  ("ไม่ใช่คุนสร้าง script เอง on the fly ไงเราต้องมี tool ใน office ของเราเอาไว้")
- **บัญชี Google:** บัญชีของเจ้าของที่เป็นเจ้าของโปรไฟล์ ใช้สร้าง Google Cloud project ด้วย
  (อีเมลไม่เขียนใน repo นี้เพราะ repo เป็น public)
- **Search Console รวมด้วย** ยืนยันด้วย DNS ไม่แก้โค้ด ("รวมเข้าไว้เลย ถ้าทำง่าย และ ควรทำ")
- **ลิงก์ที่มีรหัส:** ใช้ระบบโพสต์เดิม (`/p/F<n>`) ทั้งลิงก์ในโปรไฟล์ Maps และลิงก์ใน broadcast
  ระบบนับเป็นตัวเลขต่อวันต่อชนิด (`post_hits`) ไม่เก็บข้อมูลคนคลิก
- **รีวิว:** ขอจากคนที่ได้รับของแล้วเท่านั้น ไม่ให้ของแถมแลกรีวิว (กฎของ Google)
  เจ้าของส่งลิงก์รีวิวในแชตทีละคนเองได้ด้วย ("ผมจะได้ทำเองได้ด้วย")
- **broadcast:** office ร่าง คำนวณโควตา ส่งทดสอบหาเจ้าของคนเดียว แล้วส่งจริงเมื่อเจ้าของพิมพ์ "ส่ง" เท่านั้น
- **หลักเก็บบริบท (เจ้าของเสนอ agent เพิ่มเงื่อนไข):** ระบบควรเก็บสิ่งที่เกิดจริงในการขายและการทำงานให้ agent เห็นมากที่สุด
  ในรูปตัวเลขและเหตุการณ์ ไม่เก็บข้อความแชตหรือข้อมูลคนเกินจำเป็น (PDPA)
  และเพิ่มช่องเก็บเมื่อมีคำถามที่ตอบไม่ได้ ไม่เพิ่มล่วงหน้า

## หลักฐานตอนเปิด (2026-10-25, praneet-web origin/main 883fc16, praneet-office origin/main 159216d)

- **Google Business Profile API:** ต้องยื่น "Application for Basic API Access" ด้วย project number ของ Google Cloud project
  โปรไฟล์ต้องยืนยันมาแล้ว 60 วันขึ้นไปและมีเว็บไซต์ Google แจ้งว่าพิจารณาภายใน 14 วัน
  สิทธิ์ให้เป็นราย project ถ้าโควตาเป็น 0 แปลว่ายังไม่ได้สิทธิ์
  (developers.google.com/my-business/content/prereqs และ /faq อ่านเมื่อ 2026-10-25)
  API ถามตอบ (Q&A) ปิดไปตั้งแต่ 2025-11-03
- **LINE:** reply ไม่นับโควตา push, multicast, broadcast และ narrowcast นับรายคนที่ได้รับ
  เกินโควตาแล้ว LINE ไม่ส่งเลยสักคน (developers.line.biz pricing และ FAQ)
  แผนฟรีของ OA นี้ 300 ข้อความต่อเดือน `bun run line check` อ่านโควตาได้อยู่แล้ว ยังไม่มีคำสั่งส่ง
- **ลิงก์โพสต์:** `lib/posts.ts` รหัส `F<n>` ระบบตั้งเอง ลิงก์ไป `/` หรือหน้า lot เท่านั้น
  `post_hits` หนึ่งแถวต่อโพสต์ต่อวันต่อชนิด (open, line) ไม่นับบอทพรีวิว
  cookie `pn_post` อยู่ 1 วัน ออเดอร์ผูกกับโพสต์ผ่าน `orders.post_id`
- **ที่มาของออเดอร์:** `orders.came_from` มี check constraint ในฐานข้อมูล
  (`migrations/005_sales.sql`: facebook_group, marketplace, referral, returning, other)
  และรายการเดียวกันใน `lib/order-format.ts` การเพิ่ม "Google Maps" จึงต้องมี migration
- **Merchant Center:** Google เสนอให้ผูกกับโปรไฟล์ เพื่อแสดงสินค้าบน Maps ร้านขายส่งชุดละ 100 ต้นขึ้นไปและต่อราคาในแชต
  จึงไม่เข้ากับรูปแบบนี้ ถ้าวันหนึ่งใช้ การยืนยันเว็บใน Search Console ทำให้ข้ามขั้นยืนยันเว็บของ Merchant Center ได้

## ขั้น 0 — ทำได้ทันที ไม่ใช่ slice ไม่ต้องรอ go

ฝั่งเจ้าของ:

1. สร้าง Google Cloud project และยื่นฟอร์มขอสิทธิ์ API ก่อนอย่างอื่น เพราะต้องรอราว 14 วัน
2. เพิ่ม `ptplant.com` ใน Search Console แบบ Domain property และใส่ TXT record ที่ Namecheap
   ข้อมูลเริ่มเก็บหลังยืนยันเสร็จ จึงควรทำเร็ว
3. ส่งภาพหน้าจอหน้า Performance ของโปรไฟล์ร้าน ย้อนหลัง 6 เดือน (การโต้ตอบ, คนเห็นโปรไฟล์, คำค้นหา)
4. ส่งลิงก์ขอรีวิวให้ลูกค้าที่เคยซื้อจริงทีละคนในแชต

ฝั่ง agent ตามคำของเจ้าของ:

5. สร้างโพสต์ "Google Maps" ด้วย `posts new` (เป้าหมาย `/`) แล้วเจ้าของเปลี่ยนช่องเว็บไซต์ในโปรไฟล์เป็น `www.ptplant.com/p/F<n>`

## ขอบเขต

- **ไม่ทำ:** Merchant Center และสินค้าในโปรไฟล์ (เจ้าของ: "น่าจะ ต้องมานั่งคุมหลายที่อีก เรามี platform ส่วนตัวของเราอยู่แล้ว"),
  การแก้โปรไฟล์ โพสต์ หรือตอบรีวิวผ่าน API, รายงานที่รันเอง, หน้า dashboard ของ Google ใน `/ops`,
  Google Analytics, การเก็บข้อความแชต, การ broadcast อัตโนมัติ, การแบ่งกลุ่มผู้รับ, การซื้อแพ็กเกจ LINE,
  การเปลี่ยนชื่อร้านเพื่อแก้เรื่อง "ป้าปราณี" ก่อนเห็นตัวเลข
- **คุยกันทีหลัง ไม่อยู่ในแผนนี้:** ที่เก็บ "ลูกค้าทักแล้วไม่ซื้อ เพราะอะไร"

  script พิมพ์ได้แค่ชื่อ key ไม่พิมพ์ค่า
- คำสั่งที่เปลี่ยน production (migration, deploy) และการส่งข้อความ LINE ทำตามคำของเจ้าของในแต่ละ slice
  agent ทำเองได้ ถ้า harness ปฏิเสธ ส่งให้เจ้าของกด
