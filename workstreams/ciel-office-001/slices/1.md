# 1. Claude Code sessions: card, voice and PRs

Claude Code is where the owner works most, so it proves the whole path first.

1. **Repository.** Create private `mojisejr/ciel-office`, seed `main` once,
   clone it to `/Users/non/ghq/github.com/mojisejr/ciel-office`, and register
   `projects/ciel-office/project.yaml` in CIEL with its local binding.
2. **Office code** (Bun, TypeScript), on a topic branch with a draft PR:
   - the hook entry and worker described in the plan;
   - Stop: summary card to Discord and one spoken sentence;
   - Notification (permission wait): a short spoken line naming the project,
     no summary and no Discord;
   - `--dry-run` that prints the card and the sentence without sending;
   - a runbook in Thai: install, the secret file, removal.
3. **Tests** on recorded sample payloads, with fake `say`, `gh`, `claude` and
   webhook:
   - the summariser's environment has no `ANTHROPIC_API_KEY`;
   - with `CIEL_OFFICE_INNER` set the hook does nothing;
   - URLs on the card all appear verbatim in the message;
   - summariser, `gh` and Discord failures each give the fallback the plan
     names;
   - a malformed payload is announced, not dropped.
4. **Install** the two hook entries in `~/.claude/settings.json` on the owner's
   word, after showing the exact entries.

Acceptance:

- In a real session the owner hears the sentence and receives the card on his
  phone within about 15 seconds of the turn ending, and the session did not
  wait for it.
- A real permission prompt is announced by voice.
- One real `claude -p` run with the key removed produces a summary, proving the
  login is used.
- The card shows the open non-draft PR count from GitHub, and only links the
  session wrote.
- Removing the hook entries restores the previous settings byte for byte and
  no office process runs at the next turn end.
- The office tests pass; CIEL `bun run check` passes; no file in `ciel-os`
  outside this workstream and `projects/ciel-office/` changed.
