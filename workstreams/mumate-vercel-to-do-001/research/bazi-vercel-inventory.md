## Top findings

1. **B — Crons do not exist on DO.** If nothing replaces them: LINE alerts are never sent; accounts are never deleted (30-day deletion promise, PDPA); old quota rows are never pruned. If Vercel's crons keep running during the overlap, users get each LINE alert twice: `bazi-alerts/route.ts` sends first and marks sent afterwards (`markSent`, lines 43-57).
2. **B — A blank env line takes the whole app down.** Every field in `src/lib/env.ts` is `.min(1)` or `.url()` and `readEnv()` validates all at once (lines 3-45). `KEY=` in a docker `env_file` sets an empty string, which Vercel never does. One empty value makes every `getDatabaseUrl()`/`getCronSecret()` throw; `/api/health` then reports `db:"error"` (503), pointing at the database instead of the env file. `env/bazi.env.example` is a list of blank `KEY=` lines. Remove keys rather than leaving them blank.
3. **B — Rate limits become one shared bucket.** In-memory limiter keyed by client IP (`src/lib/rate-limit.ts:91-95`, via `llm-guard.ts`) on 11 LLM routes. On DO the FE calls bazi at `http://bazi:3000`, skipping Caddy: no `X-Forwarded-For`, every user keyed `"unknown"`; the FE does not forward the client IP. Result: 15 requests/min and 30 free LLM calls/day per feature for the whole user base; `LH_DAILY_BUDGET_THB=100` becomes one global cap. (While the FE is on Vercel, users already share a few Vercel egress IPs.) Fix: FE forwards a trusted client-IP header or anonId and bazi trusts it only from the internal network, or change the limits.
4. **B — Env parity.** The infra key list (pulled 2026-09-20) is missing keys the code reads: `CRON_SECRET`; `LINE_CHANNEL_ACCESS_TOKEN`, `LINE_CHANNEL_SECRET`, `LINE_LOGIN_URL`, `LINE_LOGIN_CHANNEL_ID`; `ADMIN_DOCTRINE_TOKEN`; `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `SUPABASE_*_BUCKET`; `RESEND_API_KEY`, `RESEND_FROM`; `LH_*`, `LOUISE_HAY_*`, `QI_GATE_OPENWEBUI`, `OPENCODE_BASE_URL`, `ANTHROPIC_PROXY_URL`/`ANTHROPIC_BASE_URL`, `RECTIFICATION_MAX_LLM_CALLS`, `OPEN_WEBUI_TRIAGE_MODEL`/`OPEN_WEBUI_GEMINI_MODEL`.
   - `ADMIN_DOCTRINE_TOKEN` fails open: unset → about 11 admin routes let anyone in (almanac PUT/DELETE, knowledge-override, doctrine routes, reading/newdata, sacred-map and upload, matching, divine-cards/images). E.g. `src/app/api/almanac/route.ts:31` `if (!expected) return true;` (re-verified by the HQ session).
   - DB URL silent fallback: `getDatabaseUrl` uses `APP_DATABASE_URL ?? DATABASE_URL` (`env.ts:49`); the example's `DATABASE_URL`/`PG*`/`NEON_*` look like Vercel's Neon integration. Missing `APP_DATABASE_URL` → bazi connects to the other database and still reports healthy.
   - Either the pull missed these keys or they are unset on Vercel today (then production crons already 401 and admin routes are already open). Reconcile against the Vercel production env before the flip (owner-run).
5. **B — Production hostname is `bazi-sft-dataset.vercel.app`, a Vercel-owned name that cannot move by DNS.** Pointing at it: FE `BAZI_BASE_URL` on Vercel; FE hard-coded `DEFAULT_BAZI_WHATIF_URL` (`mootech-fe pages/api/what-if/generate.ts:3`; `BAZI_WHATIF_URL` is not in infra `fe.env.example`); bazi `SHARE_URL` (`src/components/bazi/what-if/WhatIfExperience.tsx:45`); the LINE webhook URL and LIFF endpoint URL in the LINE console; any Open WebUI or other `/api/v1/*` client. A bazi production Caddy block is still to come. Owner decision: keep the Vercel project alive as a redirect for old shared links, or not.
6. **Found in passing (not Vercel-related, live on production): account-purge purges users who cancelled.** The cron selects only `purgeAt <= now` with no status filter (`cron/account-purge/route.ts:41-44`); cancelling sets `status:"canceled"` but keeps `purgeAt` (`account/delete/route.ts:91-94`). A user who cancels is still purged (16 tables deleted) on the original date; already-purged ids are processed again daily. Re-verified by the HQ session: the loop (lines 46-72) has no status check either.
