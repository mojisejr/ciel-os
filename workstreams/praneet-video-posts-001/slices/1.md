# 1. One approved story becomes a postable video through office

## Result

From a topic/document given in chat, the agent proposes a current creative
treatment, the owner approves a fact-checked storyboard, and office produces an
actual video and post package the owner can publish. This slice establishes
only the minimum tools needed by that episode. It does not deliver the growth target.

## Scope and order

1. Read office's posts runbook and the unmerged `posts-text-style` rule. Pass the
   child repository's clean-main gate before tracked changes. Preserve the known
   untracked `posts/.DS_Store`; use a suitable clean checkout or a non-destructive
   machine-local workaround for the gate, without deleting unrelated material.
   Coordinate against active orchard/nursery/Maps edits.
2. Place the confirmed page brief and production loop in office, with pointers
   from the existing posts workflow. Keep ordinary recordkeeping and generation
   commands usable by an agent in a fresh session; no additional LLM API is
   needed to perform the creative work already done in this chat.
3. Prove local rendering with the chosen free toolchain. Inspect the pinned
   dependencies/license and containment of any installer before use; a renderer
   must not silently enable paid cloud/media services or global CIEL integration.
   Use frame/time-driven animation that survives export, and keep outputs ignored.
4. Establish safe Gemini usage within the plan's 100-THB ceiling before a paid
   call. The minimum cost accounting must include reservations for pending calls,
   charged retries and previous use in the month; test refusal near/exceeding
   the limit and unknown-balance behavior without spending money. Existing audio
   can be reused. If the key or cost bound is unavailable, prepare the story,
   code and local preview while the audio call waits for that prerequisite.
5. Research accessible references, their dates/performance when visible, and
   candidate topics. Recommend one and explain how Praneet's own content fits.
   Do not manufacture evidence that a style is trending or a topic is seasonal.
6. Prepare one storyboard: full narration; scenes and rough timings; 3-6 code
   keyframes; sources for material claims; the visual and voice direction; what
   the viewer learns; any invitation to follow or visit the shop; and expected
   external usage. The initial clip may be roughly 30-45 seconds, adjusted to
   the approved story rather than forced to fit an unsupported claim.
7. Obtain the owner's story approval before full production. Store a concise
   approval of the specific revision, not a transcript or session locator.
   Then build the episode, generate approved narration within budget, align
   visuals/captions to actual audio, and inspect playback plus representative
   frames. Code may use 2D/3D and a speaking character when the approved story
   needs one; realistic people, cartoons and lip-sync are not mandatory.
8. Deliver an actual MP4 and preview in chat/local files, plus cover/post copy
   and existing F-link draft. Use the existing `/ops` API for that draft only
   after the owner's story/production approval authorizes it. No direct database
   write, video upload or storage charge is assumed. Preserve the existing post
   text rule and link/LINE/order tracking.
9. Have the owner review and transfer/download the file to his posting device,
   publish it himself, and share the URL and available early feedback. Record
   what was published, the exact file revision and the feedback; absent Insights
   is unknown and may be supplied later, not an invented zero.

## Acceptance / DoD

- A new agent can find the page agreement, input/sources, approved storyboard,
  episode code, final file revision and next action through office's runbook.
- The owner saw enough in the storyboard/keyframes to approve the content and
  treatment before full production; important factual unknowns were resolved or
  excluded explicitly. Approved agricultural facts have cited evidence.
- A real code-rendered MP4 plays on the owner's intended device. Text is readable,
  audio/captions/motion agree, the ending is intact, and the owner can request a
  local revision. The actual render time and owner's handling time are recorded.
- Post text and the F-link are available through the existing system. The owner
  can take the file and publish by hand, and one real publication URL is recorded.
- A cost record shows the known monthly balance, reservations/settled usage and
  the conservative bound for every Gemini request; refusal checks pass. No paid
  API call occurs while its cost cannot be bounded within 100 THB for the month.
- No additional paid subscription, cloud renderer, Facebook API, business/tax
  paperwork, paid advertising or automatic publishing was required by this slice.
- Relevant child checks pass; pre-existing unrelated work is preserved; child
  changes and slice closeout follow the owner-reviewed PR workflow.

## Owner inputs and remaining gates

Owner material/topic or permission to select from agent proposals; Gemini
credentials in an owner-controlled ignored location and billing/balance evidence
before paid use; story/voice/visual approval; final preview feedback and manual
publication; child PR merge review. The 100-THB ceiling and scoped parallelism
are already approved and must not be re-requested as routine setup permissions.
