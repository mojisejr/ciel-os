# 1. Record who used what

Counting starts the day this ships and cannot reach back, so it goes first.

1. **fe** (`pages/api/chat/bazi.ts`): send the member id to bazi with each chat
   request, server to server, as the `x-openwebui-user-id` header that bazi
   already reads.
2. **bazi**: every usage log row carries the member id.
   - Chat already passes it once the header arrives; `mate_ai_chat_meta` then
     records persona, topic and timeframe, with no text.
   - Oracle and divine card routes pass the `anonId` they already hold.
   - The narrate route (เซียมซี, ทำนายเบอร์, ปฏิทิน) and `/api/reading/topic`
     receive the id from bazi's own pages and pass it on.
3. **Staging rehearsal** before production, on a refreshed staging copy:
   - walk chat, both card decks, เซียมซี, ทำนายเบอร์, a reading and ปฏิทิน
     as a test member;
   - count on `pgstaging` that each new row carries the member id;
   - check QI is charged once per chat question;
   - check that chat card draws still work.
4. **Release** with the team's next release; the owner presses
   promote-production.

Acceptance:

- On staging, every feature walked writes usage rows with the member id, and
  chat writes `mate_ai_chat_meta` rows with a topic and no text.
- QI is charged once per question, as before.
- No migration. Tests cover the forwarded header and each route passing the id.
- After release, on the owner's word, a production count shows new rows
  carrying the member id for each feature.
- No rise in production 5xx in the release window.
