## Objective and owner agreement

เปิดร้านรับจัดบรรณานุกรม APA 7 (ไทย-อังกฤษ) บน Fastwork ลูกค้าส่งไฟล์มา เราส่งไฟล์กลับ
ระบบเป็นคนทำงาน ส่วนเจ้าของคุยกับลูกค้าใน Fastwork และดูเฉพาะรายการที่ตัวตรวจเด้งขึ้นมา
เป้าหมายระยะแรกคือมีรายได้จริงและได้ประสบการณ์ เป้า 5,000 บาทต่อเดือนไม่เร่ง
และคาดว่าจะต้องมีบริการจัดรูปเล่มวิทยานิพนธ์ก่อน (ตัดสินที่ G3)

เจ้าของตกลงใน syncup วันที่ 2026-10-07 ว่า:

- **ออฟฟิศแบบ mumate-infra:** repo `ref-office` เป็น public ใช้ license PolyForm Noncommercial 1.0.0
  ในนั้นมี runbooks, ความรู้, เครื่องมือ และ jobs (jobs ไม่เข้า git)
- **agent เป็นคนทำงาน:** ทำใน session ออฟฟิศที่แยกจาก session เขียนโค้ด ใช้ subscription ไม่ใช้ API key
  สร้างระบบด้วย Opus รับงานลูกค้าด้วย Sonnet และสลับเป็น Opus เมื่อเจอรายการยาก
  วิธีเลือกโมเดลต้องเขียนเป็น runbook
- **รับงาน:** เจ้าของส่งไฟล์และข้อความลูกค้ามาในแชทกับ agent จาก Mac
  การติดต่อลูกค้า การส่งงาน และการแจ้งสถานะอยู่ใน Fastwork ทั้งหมด ไม่มีหน้าติดตามงาน
- **สินค้า:** งาน 2 แบบ คือแก้รูปแบบอย่างเดียว และแก้รูปแบบ + ตรวจอ้างอิงในเนื้อหาเทียบกับบรรณานุกรม
  ส่งคืนเป็น .docx + .pdf + รายงานการแก้
- **ราคา:** แพ็กเกจ เริ่มต้น 250 (≤12 รายการ) / ทั้งบท 500 (≤25 รายการ ส่วนที่เกินรายการละ 20)
  / ด่วน 3 ชม. 875 (≤25 รายการ ส่วนที่เกินรายการละ 35, ช่วง 09–21 น.) แก้ได้ 3 ครั้ง งานปกติส่งใน 1 วัน
- **เส้นที่ไม่ข้าม:** ไม่แต่งรายการอ้างอิง ไม่หาอ้างอิงเพิ่ม ไม่เขียนเนื้อหา
  ลบไฟล์ลูกค้าหลังส่งงาน 30 วัน ไม่ติดต่อหรือส่งงานนอก Fastwork
  เจ้าของแจ้งว่าปิด setting ที่ให้นำบทสนทนาไปใช้ปรับปรุงโมเดลแล้ว
- **dogfood:** เพิ่มเข้า G1 ตามคำขอเจ้าของ ใช้เอกสารจริงจากอินเทอร์เน็ต + เอกสารสร้างเลียนแบบกรณียาก 10–20 ชุด
- **บัญชี Fastwork:** เจ้าของสมัครแล้ว แบบร่างหน้าบริการกรอกได้ แต่ห้ามส่งตรวจสอบจนกว่าจะผ่าน G1

## Owner revision 0.2 — G1 runs alongside the listing review

หลัง merge slice 3 เจ้าของเห็นว่าระบบพร้อมส่งงานแล้ว และอยากเรียนรู้จากลูกค้าจริงว่าต้องการงานแบบไหน
จึงตกลงปรับ G1 เมื่อ 2026-10-07 ดังนี้:

- **dogfood ลดเหลือ 3–5 ชุด** จากเอกสารสาธารณะจริง ทำระหว่างรอ Fastwork ตรวจหน้าบริการ ไม่ต้องรอให้เสร็จก่อน
  ถ้าเจอปัญหาร้ายแรงก่อนได้ออเดอร์แรก ให้ปิดหน้าบริการชั่วคราว
- **วัด token และเวลาเจ้าของต่องานจากออเดอร์จริง 3 งานแรก** แทนการวัดจากการซ้อม (ย้ายไปอยู่ใน slice 6)
- **แก้ข้อความหน้าบริการก่อนส่งตรวจสอบ:**
  - ปรับเฉพาะ "ลำดับ ฟอนต์ และรูปแบบ" ตามคู่มือสถาบัน
  - ขอไฟล์ Word (.docx) ไฟล์ PDF รับได้แต่ช้ากว่า
  - ส่วนราคาให้ตรงกับแพ็กเกจ
- **ที่มาของการขอไฟล์ Word:** ข้อความที่ดึงจาก PDF ภาษาไทยเสีย (สระอำหาย และมีช่องว่างแทรกกลางคำ)
  งานที่ลูกค้าส่ง PDF มา agent ต้องอ่านหน้า PDF ด้วยตาแทนการดึงข้อความอัตโนมัติ

### 3. Pipeline tools, checker, golden set

**Result:** คำสั่งเดียวเปลี่ยนไฟล์ลูกค้าเป็นชุดส่งงาน และตัวตรวจไม่ยอมปล่อยงานที่ไม่แน่ใจ

**Scope:**
- **ดึงข้อมูล:** แยกรายการอ้างอิงและการอ้างอิงในเนื้อหาจาก .docx หรือข้อความ
- **แยกส่วนรายการ:** agent แปลงรายการเป็น CSL-JSON ที่ผ่านการตรวจ schema
- **ตรวจข้อมูล:** ตรวจกับ Crossref/DOI
- **จัดรูปแบบ:** pandoc citeproc + `apa.csl` + กฎภาษาไทย (ไม่กลับชื่อ ใช้ พ.ศ. ใช้ "และ" เรียงตามอักษรไทย)
- **สร้างไฟล์:** .docx ด้วย reference doc (ย่อหน้าแบบห้อย 0.5 นิ้ว ระยะบรรทัดเท่า ฟอนต์ตามที่ตั้ง)
  และ .pdf ผ่าน LibreOffice ใน Docker
- **ตรวจกับเนื้อหา:** จับปีไม่ตรง อ้างถึงแต่ไม่มีในบรรณานุกรม และมีในบรรณานุกรมแต่ไม่ถูกอ้างถึง
- **รายงานการแก้**
- **ด่านกันการแต่ง:** ทุกรายการที่ส่งออกต้องย้อนไปหารายการต้นทางได้
- **สถานะต่อรายการ:** "ยืนยันแล้ว" หรือ "เด้ง" พร้อมเหตุผล ช่วงแรกรายการภาษาไทยเด้งทั้งหมด
- **ไฟล์ EndNote/Zotero:** ตรวจเจอแล้วขอให้ลูกค้าแปลงเป็นข้อความธรรมดา
- **ชุดทดสอบเฉลย:** ประมาณ 50 รายการ จากคู่มือ ม.กรุงเทพ, Purdue OWL และตัวอย่างที่ใส่ข้อผิดพลาดไว้

**DoD / proof:**

- คำสั่งเดียว: .docx เข้าไป ได้ .docx + .pdf + รายงานออกมา
- ชุดทดสอบเฉลยผ่าน 100% และจับข้อผิดพลาดที่ใส่ไว้ได้ 100%
- test พิสูจน์ว่ารายการที่ไม่มีต้นทางทำให้ไม่สร้างไฟล์
- เปิดไฟล์ที่ได้แล้วรูปแบบหน้าถูกต้อง โดยดูจาก PDF ที่ render จริง
- ระบบทำงาน 30 รายการ (ไม่นับเวลา agent) เสร็จภายใน 15 นาที
