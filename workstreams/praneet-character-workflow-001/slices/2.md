# 2. Prove conversational reference generation and reference approval

## Scope

Use an owner-selected idea/example that is not already a turnaround sheet.
Develop an actual reference through the available built-in conversational
image-generation tool, using the selected style/runbook and no new API service.

## Acceptance

- State source-image roles, intended identity, permitted redesign and important
  invariants. Supply a reusable prompt structure grounded in those decisions.
- Produce front/side/back/oblique reference material with aligned scale/pose,
  palette, material and accessory notes adequate for one coherent 3D design.
  Inspect contradictions, missing surfaces and incidental unwanted details;
  do not assume generated views are geometrically consistent.
- Preserve generated files in Office's project asset location, version them,
  retain prompts/source hashes and record the exact reference the owner accepts.
  Do not rely only on a client cache or a disposable chat locator.
- Record native generation attempts/retries and known versus unavailable
  billing/usage data. Do not invent a per-image price for subscription usage.
- If the native capability is unavailable or exhausted, keep the supplied-ref
  entry viable and report the missing capability. Do not switch to paid
  API/CLI generation or add credentials automatically.
- Reference approval is a real owner decision. Do not begin a different
  character/model or count reference creation as final model acceptance.

## Evidence and limits

Native image generation is host assistance, not a CIEL guarantee or universal
Claude capability. Record what was actually used and tested. Identify unresolved
reference choices before the next slice; preserve the approved baseline.
