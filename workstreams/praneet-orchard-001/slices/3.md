# 3. นำเข้าจาก Sheet ซ้ำได้ และรายงานเทียบ

**ทำไม:** ช่วงที่ยังใช้ Gemini อยู่ ระบบใหม่ต้องเป็นปัจจุบัน และต้องมีหลักฐานว่าสองที่ตรงกันก่อนเปลี่ยนระบบ

1. **praneet-office:** คำสั่งนำเข้าจากไฟล์ที่เจ้าของ export จาก Sheet รันกี่ครั้งก็ไม่ซ้ำ
   - กุญแจคือ (แท็บ, เลขเดิม, เลข event ของ Calendar) เพราะเลขเดิมใน Sheet ซ้ำกันเอง และตัดแถวที่ซ้ำกันทั้งแถว
   - ทุกแถวติดป้าย "มาจาก Sheet" และเก็บเลขเดิมกับเลข event
   - ชื่อคน แปลง และวิธีจ่ายที่เขียนหลายแบบ ผูกผ่านตารางคำที่เจ้าของตรวจ คำที่ยังไม่ผูกถูกปฏิเสธพร้อมเหตุผล
   - ตารางคำเก็บที่ `.assets` (git ไม่ track) เพราะมีชื่อคน เจ้าของตรวจแล้วเมื่อ 2026-10-28 (revision 0.7)
   - ส่วนที่เจ้าของเริ่มกรอกตรงแล้ว ไม่นำเข้าตั้งแต่วันนั้น: นับจากวันแรกที่มีงานที่ไม่ได้มาจาก Sheet ใน `/ops`
2. **งานเก่าเป็นบันทึกงานอย่างเดียว (revision 0.7):** แถวของ Work_Logs ไม่บอกวิธีจ่ายรายคน จึงนำเข้าโดยไม่คิดเงิน
   ข้อความเก็บตามที่เขียนใน Sheet ไม่แปลไม่เรียบเรียง หมวดงานให้เจ้าของตรวจทีหลังผ่าน `categorize`
   ชื่อที่หมายถึงเจ้าของนับเป็น "ผมทำเอง" ข้อความที่ไม่ใช่ชื่อคนย้ายไปหมายเหตุ
3. **ประวัติเงินเก่า (revision 0.7):** Labor_Ledger แสดงในหน้าของแต่ละคนเป็น "ประวัติเก่าจาก Sheet" ดูอย่างเดียว
   ไม่นับรวมยอด ยอดค้างและหนี้เบิกยังเริ่มที่ 0 ตาม revision 0.6 เงินนับจริงตั้งแต่ที่บันทึกใน `/ops`
4. **event งานสวนที่ไม่มีในแท็บใดของ Sheet:** agent แปลงเข้าระบบ เจ้าของตรวจก่อนบันทึก ไม่มีตัวแปลงอัตโนมัติ
   ส่วน event ที่มีแถววันเดียวกันในแท็บอื่น เทียบเนื้อหาในรายงาน
5. **รายงานเทียบ:** แถวที่ตรงกัน ต่างกัน หรือมีแค่ฝั่งเดียว แยกตามส่วน
   ช่วงที่กรอกสองที่ เทียบงานและเงินของวันเดียวกันระหว่าง Sheet กับ `/ops`
6. **แปลงพันธุ์ไม้ (revision 0.7):** งาน P-4 ที่นำเข้าผูกกับรอบเสียบยอดหรือ lot ที่ praneet มีอยู่ ผ่านตารางที่เจ้าของตรวจ
   หมายเหตุใน `Nursery_Lots` ไม่นำเข้าแยก เพราะอ้างเลขงานที่นำเข้าอยู่แล้ว
   การผูกต้องไม่ทำให้ฝั่งไหนบันทึกต่อไม่ได้: lot และรอบเสียบยอดแก้ ซ่อน และบันทึกต่อได้ตามเดิม
   งานยังอยู่แม้ไม่มี lot ("ให้ sync กันแต่ไม่ทำให้ข้อมูลทั้งคู่มีปัญหา ไปต่อไม่ได้ ให้บันทึกต่อได้ก็คือจบ")
7. **`orchard add` (revision 0.7):** คำสั่งที่ agent บันทึกงานแทนเจ้าของเมื่อเจ้าของเล่าในแชต
   agent เตรียมรายการให้เจ้าของดูก่อน เขียนผ่าน API เดียวกับฟอร์ม ชื่อที่ไม่อยู่ในรายชื่อถูกปฏิเสธ ไม่เดา
   ("orchard add ผมเอาครับ ... เราทำงานด้วยกันครับ")

ยังไม่ทำใน slice นี้: การพ่น (Treatment_Logs) รอตารางของ slice 5 และรายรับรายจ่าย (Finances) รอ slice 6

## Acceptance

- รันซ้ำกับไฟล์เดิมได้ผลเหมือนเดิม และไม่มีแถวซ้ำ
- แถวที่ไม่ผ่านกติกาแสดงเหตุผลเป็นภาษาไทย ไม่ถูกเดาเข้า
- งานที่นำเข้าไม่เปลี่ยนยอดค้างหรือหนี้เบิกของใคร และประวัติเงินเก่าเห็นในหน้าคนงาน
- lot และรอบเสียบยอดที่ผูกแล้วยังแก้และบันทึกต่อได้ งานสวนยังเปิดได้ถ้า lot ถูกซ่อน
- `orchard add` เขียนงานผ่านกติกาเดียวกับฟอร์ม และปฏิเสธชื่อที่ไม่รู้จัก
- การเขียน production ทำเมื่อเจ้าของสั่งเท่านั้น จากไฟล์ export ใหม่ที่เจ้าของให้
