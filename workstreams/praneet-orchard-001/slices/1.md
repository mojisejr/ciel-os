# 1. ข้อมูลจริงและโครงข้อมูล ก่อนเขียนโค้ด

**ทำไมก่อน:** เจ้าของต้องการคุยเรื่องข้อมูลให้จบก่อนนำเข้า ให้เข้ากับวิธีที่บันทึกจริง
และให้ทั้งเจ้าของกับ agent บันทึกได้ด้วยโครงเดียวกัน slice นี้ไม่เขียนโค้ดใน repo ลูก

1. **อ่าน Calendar จริง** แบบอ่านอย่างเดียว เมื่อเจ้าของเชื่อมให้: นับ event `[Garden]`
   ดูว่า META ครบกี่อัน event ไหนไม่มีใน Sheet (เทียบกับ `calendar_event_id` ใน Work_Logs)
   รวม 8 ครั้งที่ Sync_Audit เป็น ERROR
2. **โครงข้อมูล** ที่เสนอให้เจ้าของ:
   - คนงาน, วันทำงานของคนงาน (เต็ม / ครึ่ง / ลา), งานหลายชิ้นต่อวันที่ผูกกับวันนั้น,
     โหมดค่าแรง (รายวัน, ครึ่งวัน, เหมาหรือรายชิ้น, ทีมรอตัดรอบ, เจ้าของไม่คิดค่าแรง),
     เงินเบิก การหัก การจ่าย พร้อมยอดก่อนและหลัง
   - หมวดงานเทียบกับหมวดต้นทุนของตาไก๊ และแปลง P-1 ถึง P-4 โดย P-4 ผูกกับ lot และ care ของ praneet
   - คลังยา, สูตร, การพ่นพร้อมกลุ่มยา ระยะใบ ระยะแมลง และสิ่งที่เจอ, รอบการผลิต, diary
3. **รูปแบบ event ใน Calendar:** หัวเรื่อง รายละเอียดที่ไม่มีเงิน ข้อมูลซ่อน และรอยต่อกับ event เก่า
4. **กติกานำเข้าซ้ำ:** กุญแจที่ไม่ซ้ำแม้เลขใน Sheet ซ้ำ, การรวมชื่อที่เขียนหลายแบบ,
   การแยกช่องแปลงที่เขียนรวม, ป้าย "มาจาก Sheet", การตัดนำเข้าเมื่อเริ่มกรอกตรง
5. **ภาพหน้าจอตัวอย่าง** 2–4 แบบของหน้ากรอกงานรายวันและค่าแรง บนหน้าจริงที่รันในเครื่อง
   (390 และ 1280, สว่างและมืด) พร้อมแบบที่ agent เอนไปและเหตุผล ไม่ commit ตัวอย่าง
6. **แหล่งอ้างอิงของกฎยา:** ตารางเทียบสารเดิมทีละข้อ กับ FRAC/IRAC ฉลาก และกรมวิชาการเกษตร
   ข้อไหนหาแหล่งไม่ได้ ระบุไว้ว่ายังไม่บังคับ

ไม่ทำ: migration, โค้ดใน praneet-web หรือ praneet-office, อ่านหรือเขียน production, สร้างกุญแจ, เขียน Calendar

- ผลที่ตกลงบันทึกเป็น plan revision 0.2 ที่ขัด slice 2–7 ให้ชัด แล้วขอ go ของ slice 2
