# 2. คนงาน งานรายวัน ค่าแรง และเงินเบิก

**ทำไมก่อน:** เป็นส่วนที่เจ้าของใช้จริงทุกวัน เรื่องเงินต้องแม่นยำ และทุกงานผูกกับค่าแรง

1. **praneet-web ข้อมูล:** migration แบบเพิ่มอย่างเดียว
   - แปลง P-1 ถึง P-4 (P-4 ผูกกับ lot ของร้าน), คนงาน (ประจำ / รายวัน / ทีมเหมา, ค่าแรงตั้งต้น), ชนิดงานที่เจ้าของเพิ่มเองได้
     พร้อมหมวดต้นทุนของตาไก๊ที่ agent ผูกให้ และว่าเป็นงานเหมาหรือไม่ (หน่วย ราคาต่อหน่วย)
   - งาน: วันที่ ชนิดงาน แปลงได้หลายแปลง คนได้หลายคน หรือเจ้าของทำเอง หมายเหตุ จำนวนถ้าเป็นงานเหมา
   - ค่าแรง**คำนวณจากงาน**: คนที่มีชื่อในงานของวันนั้นได้ 1 วัน เจ้าของแตะเป็นครึ่งวันได้ ไม่มีงานคือไม่ได้ ไม่มีช่องลา
     งานเหมาสะสมจนตัดรอบ เจ้าของทำเองไม่คิดค่าแรง
   - เงิน: แต่ละคนมียอดค่าแรงค้างจ่ายกับเงินเบิกค้าง คำนวณจากรายการเท่านั้น เบิก, เคลียร์ค่าแรง (โอน เงินสด เติมมือถือ หักเบิก)
     แสดงยอดก่อนและหลังทุกครั้ง ยอดยกมาตอนเริ่มเป็นยอดที่เจ้าของยืนยัน
   - แก้หรือซ่อนได้ ไม่ลบจริง ทุกการเปลี่ยนเข้า `audit_events`
2. **praneet-web หน้าจอ (ตัวอย่างรอบ 2 แบบ 1 ที่เจ้าของเลือก):**
   - **หน้าของวัน:** งานจัดตามแปลง ค่าแรงบรรทัดเดียว ปุ่ม "+ เพิ่มงาน" ติดล่างจอ หน้าไม่ยาวขึ้นตามจำนวนคน
   - **หน้าเพิ่มงาน:** แปลง · ใครทำ · ทำอะไร · หมายเหตุ ปุ่ม "บันทึก แล้วเพิ่มต่อ" ติดล่างจอ
     อยู่หน้าเดิมและตั้งแปลงกับคนตามงานก่อน เพราะเจ้าของบันทึกเป็นชุดตอนเย็น หรือทันทีก็ได้
   - **ใครทำ:** ปุ่มเฉพาะคนที่มาใน 14 วันล่าสุด เลือกได้หลายคน ทีมเหมาเป็นปุ่มเดียวได้ คนอื่นค้นชื่อ รับวันละราว 15 คน
   - **ทำอะไร:** ปุ่มงานที่ใช้บ่อยของแปลงนั้น 6–8 ปุ่ม เรียงคงที่ ปรับสัปดาห์ละครั้ง ปักหมุดได้ ไม่เจอก็พิมพ์ คำใหม่ใช้ได้ทันที
   - ช่องจำนวนขึ้นเฉพาะงานเหมา พ่นยาไปฟอร์มของตัวเองใน slice 5
   - ไม่มีป๊อปอัป ใช้ชิ้นส่วนกลางของหลังบ้านตาม `DESIGN.md`
3. **API สำหรับ office:** เขียนงานและการเงินผ่านกติกาเดียวกับฟอร์ม
4. **praneet-office:** คำสั่งอ่านงานและยอดค่าแรง คำสั่งที่ agent ใช้ผูกชนิดงานกับหมวดให้เจ้าของตรวจ และ runbook ถ้าเจ้าของเห็นว่าจำเป็น
