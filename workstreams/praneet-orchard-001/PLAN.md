## เป้าหมายและข้อตกลงกับเจ้าของ

เจ้าของบันทึกงานสวนมาตั้งแต่ 2026-08-09 ด้วย Gemini Spark: งานลง Google Calendar พร้อมบล็อก META
แล้วตัวแปลง Calendar → Sheet ให้ AI เขียนลง Sheet "CIEL Orchard & Labor Engine" (21 แท็บ)
ระบบใช้ได้จริง แต่ AI บันทึกไม่แน่นอน: ตัวแปลงพลาด 8 จาก 46 ครั้ง (AI ตอบ JSON ครอบด้วย code fence)
เลข LOG ซ้ำ 13 เลข และค่าเดียวกันเขียนหลายแบบ เช่น `pay_mode` 37 แบบสำหรับราว 7 ความหมาย
(อ่านจาก xlsx ที่เจ้าของ export ไว้ใน `.assets/orchard-decision/from-gemini-spark/`, git ไม่ track)

เจ้าของยืนยันข้อตกลงนี้เมื่อ 2026-10-27 หลัง syncup 3 รอบ ("ยืนยันครับทำพร้อมกันได้เลย")

- **ผลที่ต้องการ:** งานสวน (เฉพาะงานสวน) อยู่ในฐานข้อมูลของ praneet เป็นตัวจริงแหล่งเดียว
  เจ้าของบันทึกเองผ่าน `/ops` ทำงานกับ AI ได้เหมือนเดิมทุกอย่าง และแน่นอนกว่าเดิม
- **AI:** agent ทุกตัว (Claude, Codex) ทำงานผ่าน chat session ใน `praneet-office` ไม่มี AI API
  อ่านผ่าน role อ่านอย่างเดียว เขียนผ่าน API ของ `/ops` ที่โค้ดตรวจข้อมูลเสมอ
  งานไหนต้องมี script หรือ runbook คุยกับเจ้าของก่อนทำทุกครั้ง
- **Calendar:** ระบบเขียนให้ทางเดียว ลงปฏิทินเดิม event ของระบบใหม่มีข้อมูลซ่อน (`extendedProperties`)
  บอกที่มาและเลขรายการ แก้รายการแล้วแก้ event เดิม หัวเรื่องไทยต่างจาก `[Garden] [Log]` ของเดิม
  ระบบใหม่ย้อนประวัติเก่าผ่านเลข event ที่ Sheet เก็บไว้ ไม่ให้ AI อ่านข้อความปฏิทิน
  ปฏิทินมีไว้ดูเร็ว ๆ บนมือถือและให้คนในบ้านดู จึง**ไม่มีจำนวนเงินใน event**
  ("มันต้อง seamless และไม่ขัดกัน แต่มีรอยเชื่อม ที่ทับกันที่เข้าใจได้")
- **จัดยา (สำคัญที่สุด):** agent ค้นจากประวัติการพ่นและคลัง จัดชุดที่ไม่ตีกัน บอกลำดับเทตามหลักสากล
  และอธิบายเหตุผล โดยคิดจาก**กลุ่มยา (FRAC/IRAC) ไม่ใช่ชื่อยา** รอบก่อนพ่นกลุ่มไหน ต้องสลับไหม
  ระยะใบและระยะแมลงอยู่ตรงไหน เจออะไรจริงในสวน ให้คุ้มค่าและถูกจังหวะ
  agent ไม่บันทึกการพ่น เจ้าของพ่นแล้วบันทึกเอง (เปลี่ยนยาบางตัวหน้างานได้) หรือบอกให้ agent บันทึกหลังพ่น
  สูตรที่เจ้าของเลือกบันทึกเป็นสูตรประจำได้เมื่อเจ้าของสั่ง กฎยาทุกข้อต้องมีแหล่งที่ตรวจได้ก่อนบังคับในโค้ด
- **ค่าแรง:** รายวัน (1 วันหรือครึ่งวัน ไม่ว่าทำกี่งาน) เหมา หรือรายชั่วโมง จ่ายทั้งทีมหรือรายคน (0.3, slice 2)
  เจ้าของทำเองไม่คิดค่าแรง เงินเบิกหักตอนจ่าย ทุกการจ่ายแสดงยอดก่อนและหลัง
  หมวดงานใช้ชุดเดียวกับหมวดต้นทุนของตาไก๊ (`dac2-durian-smart-account`)
- **คลังยา:** มี / เหลือน้อย / หมด และเพิ่มของที่ซื้อใหม่ได้ เจ้าของพิมพ์ชื่อการค้า ขนาด ราคา
  agent เติมสารออกฤทธิ์และกลุ่มจากฉลาก ติดป้ายรอเจ้าของยืนยัน
- **diary:** บ่นได้ตามจริง เลือกแปลงหรือไม่ก็ได้ พิมพ์ใน `/ops` หรือบ่นกับ agent แล้ว agent บันทึกเมื่อสั่ง
  เก็บตามคำพูด ไม่ขึ้นปฏิทิน ให้ agent ทุกตัวเข้าใจความคิดและบริบทของเจ้าของ ณ ตอนนั้น
- **แปลงพันธุ์ไม้ P-4:** เป็นงานหลังบ้านของร้านอยู่แล้ว รวมเข้ากับ lot และบันทึกการดูแลที่ praneet มี
- **ย้ายข้อมูล:** คุยโครงข้อมูลให้เหมาะกับวิธีบันทึกจริงก่อน แล้วนำเข้าจาก Sheet ซ้ำได้ทีละส่วน
  ส่วนที่เจ้าของเริ่มกรอกตรงแล้ว เลิกนำเข้าและใช้ Sheet เป็นรายงานเทียบ งานเก่าไม่คิดเงิน (0.7)
- **สองระบบคู่กัน:** เจ้าของกรอกสองที่ ใช้ระบบเดิมจนกว่าระบบใหม่จะพร้อมจริง วันเปลี่ยนระบบเจ้าของประกาศเอง
- **ผู้บันทึก:** เจ้าของคนเดียว บัญชี `/ops` เดิม
- **ทำพร้อมงานอื่น:** เจ้าของอนุญาตให้ทำขนานกับ `praneet-nursery-001` และ `praneet-gmaps-001`
  ซึ่งรอข้อมูลจากเจ้าของอยู่ทั้งคู่

## ข้อตกลงก่อน slice 14 และ 15 (revision 1.7, 2026-11-04)

เจ้าของอยากเปิดหน้า "วันนี้" แล้วรู้ทันทีว่าแต่ละแปลงพ่นยา ใส่ปุ๋ย ให้น้ำ ล่าสุดวันไหน ผ่านมากี่วัน
syncup 4 รอบ (agent อ่านงานจริงใน production แบบอ่านอย่างเดียวตามคำเจ้าของ และ research วิธีที่โปรแกรมฟาร์มแบ่งงาน)

  ให้น้ำพร้อมใส่ปุ๋ยนับทั้งสอง ราดยาเชื้อรา ฝังเข็ม ทาต้น พ่นยาฆ่าหญ้า โรยปูน ไม่นับเรื่องไหน
- **ไม่นับผิดสำคัญที่สุด:** ชื่องานปนไทยอังกฤษและงานผสม (183 คำ ไม่มีคำไหนมีหมวด) หาคำในชื่องานอย่างเดียวจะผิด
  จึงติดป้ายที่ตัวคำ เจ้าของยืนยัน และทุกการ์ดลิงก์ไปงานที่ใช้นับพร้อมวันที่
- **ผู้ใช้ใหม่ในอนาคตไม่ต้องติดป้ายทีละมาก:** คำตั้งต้นมีป้ายมาแล้ว คำใหม่ระบบเดาให้ตอนบันทึก (web app แยกไม่อยู่ในงานนี้)
- **โซนให้น้ำไม่บังคับ:** ส่วนใหญ่ให้ทั้งแปลง แปลงใหญ่อาจแบ่งโซน 1 2 3 และไม่เสร็จในวันเดียว ทำเป็น slice ถัดไป

## ข้อตกลงเพิ่มใน slice 14 (revision 1.8, 2026-11-04)

ระหว่างตรวจป้ายของคำกับงานจริง เจ้าของตอบเพิ่ม (Q17 ถึง Q24) และข้อเหล่านี้แทนข้อใน revision 1.7 ที่ขัดกัน:

- **ทำสารเป็นการ์ดใบที่สี่** แยกจากพ่นยา ("ช่วงทำดอกนี่สำคัญนะ") เรียงการ์ด พ่นยา · ใส่ปุ๋ย · ให้น้ำ · ทำสาร
- **ระบบรู้ว่าเป็นสารจากชนิดยา ไม่ใช่ชื่องาน:** ชั้นยามีชนิดใหม่ "สารบังคับออกดอก" แยกจาก "ฮอร์โมน"
  เพราะเจาะจงว่าบังคับให้ออกดอก ฮอร์โมนอื่นไม่สำคัญเท่า ทะวายกับสารมังคุดป้าย้ายมาชนิดนี้ (เขียนบน production เมื่อเจ้าของบอก)
- **ถังที่มีแต่สารนับทำสารอย่างเดียว** ถังที่ผสมยาฆ่าแมลงหรือยาเชื้อรานับทั้งทำสารและพ่นยา
- **ทำสารนับตามแปลงและผลไม้** ("แยกตามแปลง และ ผลไม้ ด้วยครับ") แถวเป็นแบบ "สวนล่าง · มังคุด"
  งานที่มีสารบังคับออกดอกให้แตะเลือกผลไม้จากรายการที่ระบบมี (ทุเรียน มังคุด) งานเก่า 3 งานอ่านผลไม้จากชื่องาน
- **พ่นเฉพาะจุดและพ่นลำต้นไม่นับพ่นยา** เป็นงานรักษาต้นป่วย พ่นยานับเฉพาะพ่นทางใบหรือพ่นทั้งต้น
- **ให้น้ำนับตามที่บันทึก:** หน้าฝนหรือวันฝนตกไม่ให้น้ำ และบางครั้งลืมบันทึก การ์ดจึงบอกว่าไม่มีบันทึกมากี่วัน ไม่เติมงานย้อนหลัง
- เจ้าของเลือกการ์ดแบบ A (แยกตามเรื่อง แปลงที่นานสุดอยู่บน และบอกชื่องานที่ใช้นับทุกแถว)

## ข้อตกลงก่อน slice 14 แบบใหม่ (revision 1.9, 2026-11-04)

slice 14 แบบแรก (ป้ายของคำ และการ์ดพ่นยา ใส่ปุ๋ย ให้น้ำ ทำสาร) merge แล้ว แต่เจ้าของเห็นแล้วไม่ตรงกับที่ต้องการ
เช่น "ขูดต้นแล้วพ่นยา" ไม่ใช่รอบพ่นยา และปุ่มกลมดูรก เขาสั่ง rollback ("rollback เลย")
ก่อน rollback ยังไม่มีอะไรเขียนลงส่วนใหม่บน production โค้ดย้อนกลับทั้งหมด ส่วน migration 027 เก็บไว้
เพราะรันบน production แล้ว คอลัมน์ว่างของ 027 ลบใน migration ของ slice 14 แบบใหม่

syncup อีก 3 รอบ แล้วเจ้าของยืนยันสรุป ("ตรงแล้ว") ข้อเหล่านี้แทน revision 1.7 และ 1.8 ที่ขัดกัน:

- **ไม่มีหมวด ไม่มีป้ายของคำ ระบบไม่เดา:** เจ้าของปักหมุด "กล่องติดตาม" เอง กล่องหนึ่งคือเรื่องเดียวแปลงเดียว
  ชื่อสั้นที่เขาพิมพ์ ต่อด้วยชื่อแปลง เช่น "พ่นยา · สวนมะขาม" นับเฉพาะงานที่เขาใส่เข้ากล่อง
- **บันทึกงานเหมือนเดิม:** งานรอบใหม่เข้ากล่องเมื่อเลือกกล่องในฟอร์ม (ส่วนที่ปิดไว้ก่อน เห็นเฉพาะกล่องของแปลงที่เลือก)
  รอบก่อนถือว่าเสร็จ ลืมใส่ก็เพิ่มจากกล่องได้ ("เพิ่มงานที่ลืม") เริ่มกล่องจากงานเก่าได้ที่หน้างาน
- **นับจากงานที่วันที่ใหม่สุดในกล่อง** งานที่ซ่อนไม่นับ และประวัติแต่ละรอบอยู่ในกล่อง
- **หน้าแรก:** กล่องที่วันมากสุดอยู่บน ไม่มีสี ปิดกล่องได้ ประวัติไม่หาย
- **สั่งในแชต:** agent ใส่งานเข้ากล่องให้ ถ้าเจ้าของไม่ได้บอกกล่อง ให้ถามก่อน
- slice 15 (โซนให้น้ำ) เขียนบนการ์ดแบบแรก ต้องคุยใหม่ก่อนเริ่ม

## ปิดงาน (revision 2.0, 2026-11-04)

เจ้าของมองว่าโซนให้น้ำจุกจิกเกินไป คนสวนแค่อยากบันทึกว่าวันนี้ให้น้ำไปกี่โซน และพอให้ครบก็บอกว่าจบรอบ
กล่องทำได้อยู่แล้ว: กล่อง "ให้น้ำ" กล่องเดียวต่อแปลง วันที่ยังไม่ครบบันทึกงานตามปกติโดยไม่ใส่กล่อง
วันที่ครบรอบจึงใส่งานเข้ากล่อง เจ้าของจึงตัด slice 15 ออก ("ใช้กล่องอ่ะ ง่าย และสบายสุดละ")
แล้วสั่งปิดงานนี้ ("ถ้าไม่มีอะไรแล้ว workstream ให้ปิดได้ปิดเลยครับ")
