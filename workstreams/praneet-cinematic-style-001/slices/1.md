# 1. Install and measure a small additive garden-style proof

## Result

The owner can inspect an actual original Blender garden result and the evidence
needed to decide whether this Mac is suitable for the next cinematic-style test.
The existing Praneet Explainer style remains intact and usable.

## Execution scope

1. Research official stable ARM64 releases and local installation requirements.
   Read current disk/RAM/OS facts. Download only from the official distribution,
   verify its published digest and macOS application trust, then install under
   the current user's Applications directory without overwriting another app.
2. Prove version/background Python execution. Keep paid credentials out of the
   render environment and avoid changing global render, shell or app preferences.
3. State a small scene/layer/frame contract before coding: full-frame warm
   garden diorama with raised mounds, credible trees, soil/root details, authored
   light and a deliberate camera move. This probe carries no agronomic recipe.
4. Produce a portrait still first at a modest resolution, measuring duration and
   process RSS. Render a few seconds of silent motion at a bounded resolution
   only when the still indicates a reasonable memory/time budget. Cap the trial
   process time and monitor its own RSS; stop only the owned render process if
   bounds are exceeded. Keep snapshots/limits distinct from hard memory guarantees.
5. Inspect the actual still, motion samples and encoded video when produced.
   State what the image demonstrates and what quality/resource issues remain.
   Use no bit-identical raster gate as a substitute for scene quality.
6. Record install provenance, measured resources, source/output hashes, run steps,
   preservation evidence and the next executable action. Keep installer, app
   bundle, .blend files and renders outside Git. Add no unrelated dependencies,
   CI changes, global hooks or reusable rendering platform.

## Acceptance / DoD

- Official Blender installed locally and signature/trust/version checks recorded,
  or a concrete verification/compatibility blocker is evidenced without bypass.
- A bounded original scene render is inspected; a short movie is attempted only
  if the still's measured footprint permits it. A resource-limited result must
  name the actual limit and not claim cinematic production readiness.
- For a successful movie: measured duration/size/fps, decode and representative
  timeline frames are checked. Preview status and absent narration are clear.
- Time/RSS and memory/swap observations are retained with their limitations.
  No other app/process is terminated and no memory pressure setting is changed.
- Parent STYLE.md and delivered episodes are unchanged; the new candidate is
  documented as additive and experimental, not the selected default.
- No paid API call, service purchase, business/tax paperwork, remote upload or
  social write was needed. Existing Gemini reservations remain unchanged.
- Narrow source/metadata checks and CIEL Wake validation pass. The owner sees
  the concrete result and can decide the scope of a further style pilot.
